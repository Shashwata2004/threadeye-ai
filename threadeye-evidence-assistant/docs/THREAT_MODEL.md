# Threat Model

This model covers the isolated fictional Evidence Assistant through Prompt 09. Document text is untrusted data. It
cannot change application policy, authorize retrieval, perform an operational decision, or become a trusted citation
merely by resembling instructions or metadata.

| Threat | Entry point | Attacker-controlled surface | Potential impact | Existing mitigation | Prompt 07 mitigation | Test coverage | Residual limitation |
|---|---|---|---|---|---|---|---|
| Direct prompt injection | Question | Query text | Policy bypass or data disclosure | Pre-retrieval request policy | NFKC normalization; hidden-control and mixed-script rejection; expanded role/instruction patterns | Direct, obfuscated and role-message cases | Pattern rules cannot recognize every paraphrase |
| Indirect injection | Retrieved document | Sanitized Markdown | Evidence instructions affect an answer | Documents stay inert; known instructions cause abstention | Canonicalized Unicode inspection covers fake roles, fenced text and hidden format characters | Five approved security fixtures and unit tests | A future generative model needs independent defenses |
| Fake system/developer roles | Question/document | Role-like prose | Instruction hierarchy confusion | No source text is executed | Role markers are classified as untrusted evidence | `test_nfkc_hidden_and_fake_roles_are_inert` | Novel social-engineering language may evade patterns |
| Citation/source impersonation | Evidence/output | Fake IDs, paths, hashes and excerpts | Unsupported claim appears grounded | Exact retrieved membership and provenance match | Recompute stored chunk hash; validate normalized length, every optional filter, bounded citation count and full extractive equality | Citation mutation suite and spoof fixture | Extractive relevance remains heuristic, not a semantic proof |
| Source metadata manipulation | Index/citation | Path, source hash, profile, version, classification | Stale or foreign source is cited | Sealed ingestion/index provenance | Complete retrieval-filter recheck at citation time | Stale span/profile/path/hash/filter negatives | Database administrator compromise is out of scope |
| Unauthorized/cross-corpus access | Ingestion through answer | Corpus, policy and approval filters | Private evidence leakage | Required filters bound in both SQL branches | Scope count before retrieval; selection and citation revalidation; leakage metrics | SQL integration and 6 negative evaluation cases | No real user/session identity service exists |
| Secret exfiltration | Question/document | Requests and fake credentials | Credential disclosure | Sanitization/redaction and request block | Unsafe question echo is sanitized; all fixture credentials are fake | Secret request and private-key non-echo tests | Entropy-based secret detection is not implemented |
| Malicious Markdown/code | Ingestion/document | Fences, comments and links | Code execution or hidden instructions | Markdown is normalized as text only | Fenced and visually hidden instructions evaluated as inert evidence | Normalization and security fixture tests | Renderer-specific attacks require UI testing if a UI is built |
| Unicode/encoding edge cases | Question/document | Homoglyphs, controls and compatibility forms | Filter bypass or identifier confusion | Strict UTF-8 input | NFKC plus hidden-control and mixed Latin/Greek/Cyrillic rejection | Zero-width, word-joiner, full-width and homoglyph cases | Single-script confusables and all writing systems need human review |
| Conflicting evidence | Retrieved results | Opposing claims | Incorrect resolution | Explicit conflict abstention | Canonicalized conflict checks and dedicated fixture | Conflict unit/evaluation cases | No temporal or authority-based conflict resolution |
| Similar irrelevant evidence | Retrieval | Semantic decoy | False answer | Multi-signal sufficiency | Domain-anchor consistency and independent adversarial holdout | Domain-shift/decoy tests | Domain anchors are a small heuristic vocabulary |
| Exact identifier confusion | Question/results | Near-match IDs | Answer about the wrong roll/evidence item | Identifier-aware selection | Case-normalized exact identifier requirement | Wrong-identifier test and held-out identifiers | OCR errors and aliases are not resolved |
| Keyword stuffing | Document | Repeated query terms | Poisoned result outranks facts | Hybrid retrieval and sufficiency | Repetition/unique-token guard rejects selected poisoned evidence | Stuffing fixture and unit test | Sophisticated low-rate stuffing may evade the heuristic |
| Vector/keyword outage | Retrieval backend | Component availability | Partial search is mislabeled successful | Branch failures raise errors | Structured stage-specific failure; no automatic degraded hybrid mode | Both branch faults injected | No high-availability backend or retry policy |
| Database outage/timeout | Scope/retrieval | Local companion availability | Fabricated response or hanging request | 5 s connect and bounded database statements | Structured fail-closed response; deterministic timeout simulation | Database unavailable/timeout/service-stopped cases | No high-availability backend or retry policy |
| Embedding/profile failure | Vector retrieval | Model/cache/profile | Wrong-space vectors or unavailable search | Pinned revision and profile key | Explicit embedding/profile fault evaluation | Genuine model tests plus injected failures | Model supply-chain trust depends on pinned cached artifact |
| Oversized/malformed input | Answer/MCP tools | Length, type and controls | Resource exhaustion or crashes | 1,000-char answer bound and structured validation | MCP top-k 5, 64 KiB response, concurrency 4, 10 s tool deadline, strict unknown-argument rejection | Length, empty, controls, mode, unknown argument, response limit and timeout tests | No public rate limiting; timed-out worker depends on the shorter DB timeout |
| Unsafe operational request | Question | Approve/reject/score commands | AI output mistaken for verdict | Request policy and limitations | Evaluated independently in both splits | Verdict/scoring cases | Human misuse of copied text cannot be prevented technically |
| Path/symlink/secret-file access | Ingestion | Manifest paths | Arbitrary local read | Exact allowlist, canonical containment, no symlinks, sensitive-path exclusion | Preserved unchanged | Foundation regression suite | Host compromise is out of scope |
| Production coupling | Architecture | Companion failures | ThreadEye inspection outage | No ThreadEye imports, DB, network or deployment dependency | Failure tests only wrap companion objects; protected hashes checked | Full regression and hash audit | Operational deployment isolation still requires team review |
| Local launcher authority | MCP process startup | Environment, config and read-only credential | Unauthorized use of the configured synthetic scope | Stdio is never claimed as authentication | Operator-owned non-writable config, exact local DB identity, required environment and fail-closed startup | Missing config, unsafe file and real stdio tests | Anyone who can launch with trusted credentials can use those limited permissions |
| Client scope spoofing | MCP tool arguments | Corpus, source, policy, profile or extra fields | Authorization elevation or cross-corpus leakage | Retrieval filters are server-owned | Fixed registry and strict middleware reject every unknown argument before SDK model parsing | Injected `corpus_id`, cross-source and malformed argument tests | Process-level credential compromise is outside application controls |
| Protocol stream corruption | MCP stdio | Logging and startup output | Client cannot parse frames or leaks diagnostics | No application prints in tool paths | Stdout reserved for SDK protocol; sanitized diagnostics and startup denial use stderr | Genuine official-client subprocess lifecycle | Third-party native library output would require dependency-level correction |
| Database credential overprivilege | MCP database connection | Runtime role grants | Evidence mutation or schema changes | Python facade has no write methods | Separate non-inheriting read-only role, SELECT-only grant, transaction read-only and exact identity check | Real UPDATE, DELETE, TRUNCATE, schema DDL and temp DDL denials | Database administrator compromise is out of scope |
| Dangerous tool exposure | MCP discovery/call | Tool registry | Filesystem, shell, SQL or operational mutation | Fixed code-defined registry | Exactly four annotated read-only tools; forbidden names absent and uncallable | Discovery allowlist and `delete_roll` negative call | A future registry change requires renewed review |
| Resource metadata leakage | MCP resource read | Resource payload | Secrets or repository/source disclosure | Only service-generated mappings | Three exact URIs, sanitized metadata, bounded payloads, no raw documents | Resource allowlist/read tests and secret scanning | Descriptions still reveal intentional fictional corpus metadata |
| Missing/forged HTTP identity | HTTP Authorization | Missing, malformed, unsigned or attacker-signed token | Anonymous evidence access or impersonation | Prompt 08 had no HTTP transport | SDK bearer middleware plus EdDSA signature, fixed alg/kid/type, issuer, exact audience, expiry/nbf, subject/client and allowlist validation | Direct verifier matrix and real HTTP 401 matrix | Local public-key replacement by the operator changes trust; host compromise is out of scope |
| Algorithm/key confusion | JWT header/signature | `none`, HMAC, unknown key ID or wrong asymmetric key | Signature bypass | None needed for stdio | One permitted `EdDSA` algorithm, exact `kid`, Ed25519 key-type/file checks | Unsigned, HS256, wrong-key and unknown-key tests | No JWKS rotation or external key discovery |
| Excess token privilege | JWT claims/tool call | Scope, role, corpus or policy claim/argument | Metadata client performs search/answer or changes corpus | Server-owned retrieval filters | Per-principal scope allowlist, request-local operation check, strict argument schemas; token never supplies corpus policy | Independent metadata client, unsupported scope, role/corpus injection | No dynamic tenant or human-user policy service |
| Cross-client identity state | HTTP connection/session | Reused connection or context | One principal inherits another's scopes | No HTTP clients previously | Stateless SDK HTTP; authentication and auth ContextVar reconstructed/reset per request | Two official clients with different tokens and denial after Client A | Bearer theft permits use until short expiry; no revocation |
| DNS rebinding/Origin abuse | HTTP Host/Origin | Host, Origin, browser CORS | Browser reaches local privileged endpoint | Loopback binding | Exact pre-auth Host/Origin plus SDK transport validation; no wildcard CORS | Wrong Host 421, wrong Origin 403, metadata/MCP wildcard absence | No trusted reverse proxy mode or TLS |
| Header/body/protocol abuse | HTTP request | Duplicate Authorization/length, method, media type, JSON, MCP version | Parser ambiguity, memory pressure or auth bypass | Existing query/result bounds | 8 KiB token, 64 KiB body, duplicate-header rejection and SDK protocol parsing | Real malformed/content/method/body/protocol negatives | Transfer/parser vulnerabilities in dependencies remain possible |
| Local HTTP denial of service | HTTP principal/IP/concurrency | Repeated or simultaneous calls | CPU/model/database exhaustion | Four tool workers, deadlines and DB timeouts | Bounded in-memory per-principal/IP windows, 1,024 keys, immediate four-request concurrency 429, worker-held semaphore | Deterministic limit/cleanup/cancellation plus real 429 recovery | Per-process only; no distributed limiter; localhost processes can rotate principals/IP context only within allowlist |
| Timed-out worker accumulation | Tool worker | Slow native inference/database work | Abandoned threads accumulate after deadline | Prompt 08 abandoned worker and released async slot | Worker-owned bounded semaphore remains held until actual exit; shorter DB statement timeout | Timeout, immediate capacity denial and later recovery test | Permanently stuck native inference can consume a slot indefinitely and cause safe unavailability |
| Security-log injection/leakage | HTTP audit event | Headers, principal, query, exception | Token/secret leakage or forged log lines | Sanitized MCP errors | Server-generated IDs, hashed principals/IPs, JSON escaping, safe categories; no queries/tokens/keys/passwords | Captured real stderr and JSON unit tests | Logs are not signed, chained or tamper-proof and persistence is operator-owned |
| OAuth overclaim | Documentation/submission | Local offline test issuer | Local bearer demo misrepresented as complete OAuth | Explicit honesty disclosures | RFC 9728 resource metadata/challenge separated from absent authorization server/onboarding | Metadata and challenge integration tests | No external AS, discovery verification, interactive consent, DCR, refresh or revocation |

The adversarial evaluation is synthetic security testing, not a penetration test or proof of production safety.
