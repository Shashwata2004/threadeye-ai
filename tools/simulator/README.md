# ThreadEye Roll Simulator

ফ্যাক্টরি ছাড়াই "চলন্ত কাপড়ের রোল"-এর ভিডিও বানানোর টুল। সাথে থাকে প্রতিটা ত্রুটির সঠিক অবস্থান (ground truth), যাতে তোমাদের AI কতটা ঠিক ধরছে তা সংখ্যায় মাপা যায়।

তিনটা স্ক্রিপ্ট:

| স্ক্রিপ্ট | কাজ |
|---|---|
| `make_roll_video.py` | রোল বানায়, স্ক্রলিং ভিডিও রেন্ডার করে, ground truth আর 4-point স্কোর লেখে |
| `sample_frames.py` | ভিডিও থেকে শুধু দরকারি ফ্রেমগুলো বের করে (AI/API-তে পাঠানোর জন্য) |
| `evaluate.py` | তোমাদের AI-এর ফলাফল ground truth-এর সাথে মিলিয়ে precision, recall আর 4-point স্কোর দেখায় |

sudo apt install ffmpeg

## ২. তিনটা উৎস (source)

### ক) `synthetic`: কোনো ডেটাসেট লাগে না

কোড নিজেই কাপড়ের টেক্সচার বানায়, তার উপর ৪ ধরনের ত্রুটি আঁকে: `hole`, `stain`, `yarn_defect`, `knot`। পুরো pipeline তাড়াতাড়ি টেস্ট করার জন্য সবচেয়ে ভালো।

```bash
python make_roll_video.py --source synthetic --roll-length-m 30 --out out_synthetic
```

### খ) `aitex`: আসল কাপড়ের ছবি (প্রস্তাবিত)

AITEX ডেটাসেটে আসল কাপড়ের লম্বা ফালি (4096×256) ছবি আছে, সাথে ত্রুটির mask। একটা GitHub রিপোতে পুরো ডেটাসেট রাখা আছে, শুধু দরকারি ফোল্ডারগুলো নামানো যায়:

```bash
git clone --depth 1 --filter=blob:none --no-checkout https://github.com/jraad/fabric_defect_detection
cd fabric_defect_detection
git sparse-checkout set --no-cone data/aitex/Defect_images data/aitex/Mask_images data/aitex/NODefect_images
git checkout
cd ..
```

Kaggle-এও পাওয়া যায়: <https://www.kaggle.com/datasets/nexuswho/aitex-fabric-image-database>

```bash
python make_roll_video.py --source aitex --dataset fabric_defect_detection/data/aitex \
  --roll-length-m 30 --tint "#3b5b8c" --out out_aitex
```

- AITEX-এ ৭ ধরনের কাপড় আছে (কোড 00–06)। রোল যেন একটাই কাপড় দিয়ে হয়, তাই `--fabric-id auto` ডিফল্টভাবে সবচেয়ে বেশি ত্রুটির ছবি আছে এমন কাপড় বেছে নেয়। চাইলে নিজে দাও, যেমন `--fabric-id 03`।
- ছবিগুলো সাদাকালো। `--tint` দিলে রঙিন দেখায়, না দিলে ধূসর থাকে।

### গ) `yolo`: Roboflow বা অন্য যেকোনো YOLO-format ডেটাসেট

ZJU-Leaper, TILDA ইত্যাদি Roboflow থেকে "YOLO" format-এ export করলে ফোল্ডার এ রকম হয়: `train/images`, `train/labels`, `data.yaml`।

```bash
python make_roll_video.py --source yolo --dataset path/to/roboflow_export --out out_yolo
```

- যে ছবির label ফাইল খালি বা নেই, সেটাকে ত্রুটিহীন কাপড় ধরা হয়।
- ডেটাসেটে ত্রুটিহীন ছবি না থাকলে আলাদা ফোল্ডার দাও: `--good-dir path/to/clean_fabric`
- ছোট ছবি (যেমন 512×512) পাশাপাশি বসিয়ে কাপড়ের পুরো প্রস্থ ভরানো হয় (`--tiles-across auto`)।

## ৩. বাস্তবের মতো মোড (ডিফল্ট)

`--mode realistic` ডিফল্টভাবে চালু থাকে। আসল inspection machine-এর উপর বসানো ক্যামেরা যা দেখবে, তার কাছাকাছি জিনিস যোগ হয়:

| কী যোগ হয় | বাস্তবে কেন হয় |
|---|---|
| **থেমে থেমে চলা** | ইন্সপেক্টর ত্রুটি দেখলে মেশিন ধীর করে থামান, কয়েক সেকেন্ড দেখেন, তারপর আবার চালু করেন। মাঝে মাঝে অকারণেও থামেন। গতি পুরোপুরি স্থির থাকে না। |
| **কাপড় পাশে সরে যাওয়া** | চলার সময় কাপড় কয়েক সেন্টিমিটার এদিক-ওদিক সরে যায় |
| **দুই পাশে আলোকিত বোর্ড** | কাপড়ের প্রস্থের বাইরে মেশিনের বোর্ড দেখা যায় |
| **কিনারা (selvage) আর পিনের ছিদ্র** | কাপড়ের কিনারা ঢেউ খেলানো থাকে। কিনারায় সারি সারি ছোট ছিদ্র থাকে, যা ফিনিশিং মেশিনের পিন থেকে হয়। **এগুলো ত্রুটি না।** |
| **ভাঁজ (wrinkle)** | কাপড় নাড়াচাড়ার ফলে হালকা ভাঁজ পড়ে। **ত্রুটি না।** |
| **আলগা সুতা** | কাপড়ের উপর পড়ে থাকা সুতার টুকরো। **ত্রুটি না।** |
| **স্টিকার** | ইন্সপেক্টর থামার পর ত্রুটির পাশে কিনারায় রঙিন স্টিকার লাগান। তারপর স্টিকারটা কাপড়ের সাথে চলতে থাকে। |
| **ইন্সপেক্টরের হাত** | স্টিকার লাগানোর সময় হাত ক্যামেরার সামনে চলে আসে, কাপড়ের একটা অংশ ঢেকে যায় |
| **আলোর ধীর পরিবর্তন** | ক্যামেরার exposure সময়ের সাথে একটু বদলায় |

ভাঁজ, সুতা, স্টিকার আর পিনের ছিদ্র ইচ্ছা করেই রাখা হয়েছে। **আসল ফ্যাক্টরিতে AI-এর সবচেয়ে বড় সমস্যা হলো এগুলোকে ভুল করে ত্রুটি ভাবা।** এগুলোর তালিকা `nuisance.csv`-এ থাকে, আর `evaluate.py` বলে দেয় কোন ভুল কোন জিনিসের কারণে হলো।

আগের মতো পরিষ্কার ভিডিও চাইলে `--mode clean` দাও: স্থির গতি, শুধু কাপড়, কোনো বোর্ড বা হাত নেই।

**সময়:** বাস্তবের মোডে রেন্ডার একটু ধীর। একটা সাধারণ ল্যাপটপে ৩০ মিটারের রোল বানাতে কয়েক মিনিট লাগতে পারে।

## ৪. আউটপুট ফাইল

| ফাইল | কী আছে |
|---|---|
| `roll_video.mp4` | স্ক্রলিং ভিডিও। কাপড় নিচ দিয়ে ঢুকে উপর দিয়ে বের হয়। নিচে একটা "SIMULATED FEED" লেখা বার থাকে। |
| `ground_truth.csv` | প্রতিটা ত্রুটি: class, রোলের কত গজে (`center_yd`), কিনারা থেকে কত দূরে (`across_cm`), আকার (`length_in`), 4-point পয়েন্ট, কোন ফ্রেমে পুরোপুরি দেখা যায়, ইন্সপেক্টর কোন ফ্রেমে থেমেছিলেন |
| `nuisance.csv` | যেগুলো ত্রুটির মতো দেখায় কিন্তু ত্রুটি না: ভাঁজ, আলগা সুতা, স্টিকার |
| `frames.csv` | প্রতিটা ফ্রেমে রোলের কোন অংশ দেখা যাচ্ছে, গতি, চলছে না থেমে আছে, কাপড় কতটা পাশে সরেছে, হাত দেখা যাচ্ছে কি না। মেশিনের মিটার কাউন্টারের মতো কাজ করে। |
| `roll_meta.json` | সব সেটিংস, `px_per_cm`, আর পুরো রোলের প্রত্যাশিত 4-point স্কোর ও PASS/FAIL |
| `roll_preview.png` | পুরো রোল এক ফিতায়। লাল বক্স মানে ত্রুটি, কমলা বক্স মানে ত্রুটি না (ভাঁজ, সুতা, স্টিকার)। |

### পিক্সেল থেকে গজ হিসাব

কাপড় স্থির গতিতে চলে না, তাই অবস্থান হিসাব করতে হয় `frames.csv` থেকে। এটা আসল মেশিনের মিটার কাউন্টার পড়ার মতোই। ফ্রেম `i`-এর `(x, y)` পিক্সেলের অবস্থান:

```
roll_y_px = roll_y_top_px[i] + y
yard      = roll_y_px / px_per_cm / 91.44
across_cm = (x - fabric_x0_px[i]) / px_per_cm
```

`roll_y_top_px` আর `fabric_x0_px` আসে `frames.csv` থেকে, `px_per_cm` আসে `roll_meta.json` থেকে। অ্যাপের traceability আর Roll Map এই হিসাব দিয়েই চলবে।

## ৫. দরকারি ফ্রেম বের করা

পরপর ফ্রেমগুলো প্রায় একই রকম, তাই সব ফ্রেম AI-তে পাঠানোর দরকার নেই।

```bash
python sample_frames.py --video out_aitex/roll_video.mp4 --meta out_aitex/roll_meta.json --out out_aitex/sampled
```

কাপড় কতটা এগোল তা দেখে ফ্রেম নেয়, যাতে পুরো রোল ঢাকা পড়ে আর পাশাপাশি দুই ফ্রেমের মধ্যে ১৫% overlap থাকে। মেশিন থেমে থাকলে নতুন ফ্রেম নেয় না। হাত দেখা গেলে কাছাকাছি হাত ছাড়া একটা ফ্রেম খোঁজে। সাধারণত মোট ফ্রেমের মাত্র ১–২% লাগে। `index.csv`-এ লেখা থাকে প্রতিটা ছবি রোলের কোন জায়গার।

## ৬. AI-এর ফলাফল মাপা

তোমাদের অ্যাপ বা API যা খুঁজে পেল, তা দুই ফরম্যাটের যেকোনো একটায় CSV-তে লেখো।

**ফ্রেম-ভিত্তিক** (প্রতিটা ফ্রেমের box, নিচের তথ্য-বার বাদে ক্যামেরার ছবির পিক্সেলে, সবচেয়ে সহজ):
```
frame,x0,y0,x1,y1,class,confidence
65,1150,700,1190,735,hole,0.82
```

**রোল-ভিত্তিক** (অ্যাপ নিজেই duplicate মিলিয়ে ফেললে):
```
center_yd,across_cm,class,confidence,length_in
1.86,92.4,hole,0.82,1.1
```

```bash
python evaluate.py --gt out_aitex/ground_truth.csv --pred my_predictions.csv --meta out_aitex/roll_meta.json
```

ফলাফলে যা পাবে:
- Precision, Recall, F1
- কোন class কত % ধরা পড়ল
- Class কতবার ঠিক বলা হলো
- AI-এর হিসাব করা 4-point স্কোর বনাম আসল স্কোর
- ভুল করে ধরা (false positive) জিনিসগুলো আসলে কী ছিল: ভাঁজ, সুতা, স্টিকার, নাকি কিনারা

ফ্রেম-ভিত্তিক ফলাফলে একই ত্রুটি কয়েকটা ফ্রেমে এলে সেগুলো একটা হিসেবে গোনা হয় (`--merge-cm`)। খুব ছোট ত্রুটি, যা এই resolution-এ চোখেই দেখা যায় না, হিসাব থেকে বাদ দিতে `--min-length-in 0.2` দাও।

**এই সংখ্যাগুলোই জাজদের দেখানোর benchmark টেবিল।** Gemini বনাম YOLO, একই ভিডিওতে।

## ৭. গুরুত্বপূর্ণ সেটিংস

| অপশন | ডিফল্ট | মানে |
|---|---|---|
| `--roll-length-m` | 30 | রোলের দৈর্ঘ্য (মিটার) |
| `--fabric-width-cm` | 150 | কাপড়ের প্রস্থ |
| `--frame-width` | 1920 | প্রস্থ বরাবর পিক্সেল। বেশি দিলে ছোট ত্রুটি ভালো দেখা যায়, কিন্তু ভিডিও ভারী হয়। |
| `--view-length-cm` | 85 | এক ফ্রেমে কাপড়ের কতটা দৈর্ঘ্য দেখা যায় |
| `--mode` | realistic | `realistic` বা `clean` |
| `--speed-m-min` | 20 | চলার সময় কাপড়ের গতি (মিটার/মিনিট) |
| `--stop-prob` | 0.85 | ত্রুটি দেখলে ইন্সপেক্টর কত সম্ভাবনায় থামবেন |
| `--pause-s` | 2.5,5 | কত সেকেন্ড থেমে থাকবেন (সর্বনিম্ন,সর্বোচ্চ) |
| `--random-stops-per-10m` | 0.6 | অকারণে থামা |
| `--drift-cm` | 1.5 | কাপড় কতটা পাশে সরে যেতে পারে |
| `--board-margin-cm` | 6 | কাপড়ের দুই পাশে কতটা বোর্ড দেখা যাবে |
| `--no-hands`, `--no-stickers` | | হাত বা স্টিকার বাদ দিতে |
| `--fps` | 30 | ভিডিওর ফ্রেম রেট |
| `--defects-per-10m` | 4 | প্রতি ১০ মিটারে গড়ে কতটা ত্রুটিযুক্ত টাইল |
| `--seed` | 7 | একই seed দিলে হুবহু একই রোল আবার তৈরি হয় |
| `--threshold` | 40 | প্রতি ১০০ বর্গগজে কত পয়েন্ট পর্যন্ত PASS |
| `--noise`, `--vignette`, `--exposure-s` | | ক্যামেরার নয়েজ, আলোর অসমতা, motion blur |
| `--debug-boxes` | বন্ধ | ভিডিওতেই ground truth box আঁকে (শুধু যাচাইয়ের জন্য, AI-কে এই ভিডিও দিও না) |
| `--no-label` | বন্ধ | "SIMULATED FEED" বার বাদ দেয় |

**PASS আর FAIL দুই রকম রোল বানাতে:** `--defects-per-10m 1` দিলে সাধারণত PASS আসে, `--defects-per-10m 8` দিলে FAIL। আসল ফলাফল `roll_meta.json`-এ দেখে নিও। Seed বদলে বদলে কয়েকটা রোল বানিয়ে রাখো, ডেমোতে কাজে লাগবে।

## ৮. সীমাবদ্ধতা

- **এটা সিমুলেশন।** ডেমোতে দেখালে "SIMULATED FEED" লেখাটা রেখে দাও। ইনপুট সিমুলেটেড হলেও AI-এর বিশ্লেষণ অবশ্যই আসল হতে হবে।
- **বাস্তবের মোডও পুরো বাস্তব না।** হাতটা সরল আকৃতির, ভাঁজগুলো শুধু আলো-ছায়া দিয়ে বানানো, কাপড় বাঁকা হয়ে চলে না, আর ক্যামেরা সোজা উপর থেকে দেখে। এই সিমুলেশনে পাওয়া accuracy-কে ফ্যাক্টরির accuracy বলে দাবি করো না।
- **ডেটাসেটের টাইলের জোড়া:** আলো মিলিয়ে নেওয়া (`flat-field`) আর জোড়ার জায়গা মসৃণ করা (`--overlap`) হয়। তবুও টাইলের সীমানায় হালকা দাগ থাকতে পারে, আর AI ভুল করে সেটাকে ত্রুটি ভাবতে পারে। AITEX-এর লম্বা ফালিতে এই সমস্যা সবচেয়ে কম।
- **ছোট ত্রুটি:** AITEX-এর nep আর fuzzyball অনেক সময় খুব ছোট। 1920 পিক্সেলে প্রায় দেখাই যায় না। দরকার হলে `--frame-width 4096` দাও, অথবা মাপার সময় `--min-length-in` ব্যবহার করো।
- **আসল মাপ:** ডেটাসেটের ছবি আসলে কত সেন্টিমিটার কাপড়ের, তা জানা নেই। তাই সেন্টিমিটার আর গজের হিসাব `--fabric-width-cm` অনুযায়ী ধরে নেওয়া। Pipeline টেস্টের জন্য এটা যথেষ্ট, তবে আসল ফ্যাক্টরির মাপ দাবি করো না।
- **AITEX-এর বাম পাশ:** কিছু AITEX ছবির বাম দিকে কাপড়ের কিনারার বাইরের অংশ দেখা যায়। তাই AITEX-এ ডিফল্টভাবে বাম দিকের ১০% কেটে ফেলা হয় (`--trim-left 0.10`)। পুরো ছবি রাখতে চাইলে `--trim-left 0` দাও।
- **ডেটাসেটের শর্ত:** AITEX আর অন্য ডেটাসেট ব্যবহারের আগে লাইসেন্স দেখে নাও, আর সাবমিশনের "Data & AI Provenance" অংশে উল্লেখ করো।
